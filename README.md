# Диагностика сетевого стека (TCP/IP, DNS, DHCP, WireGuard) в Rocky Linux

Практическая лабораторная работа по администрированию и диагностике сетевой подсистемы Linux на базе **Rocky Linux 9** в среде виртуализации **Oracle VirtualBox**.

## Цели работы
* Изучение параметров сетевых интерфейсов и таблицы маршрутизации (`iproute2`).
* Проверка работы протокола **DHCP** (процесс DORA, параметры аренды адреса).
* Диагностика **DNS**-резолвинга и отработка сценария траблшутинга при отказе DNS-сервера.
* Перехват и анализ сетевых пакетов в реальном времени с помощью **`tcpdump`**.
* Развёртывание виртуального туннельного интерфейса **WireGuard (`wg0`)** и проверка маршрутизации VPN-подсети.

---

## Стенд и инструменты
* **ОС:** Rocky Linux 9 (VirtualBox VM, сетевой адаптер `enp0s3` в режиме NAT)
* **Утилиты:** `ip` (`iproute2`), `ss`, `dig` (`bind-utils`), `tcpdump`, `curl`, `wireguard-tools`, `journalctl`

---

## Ход выполнения работы

### 1. Анализ сетевых интерфейсов и DHCP
Проверка активных интерфейсов и полученных по DHCP сетевых параметров:

```bash
ip -c a
```

**Результат:**
* Интерфейс `enp0s3` находится в состоянии `UP,LOWER_UP`, MAC-адрес `08:00:27:ee:e1:c0`.
* Получен динамический IPv4-адрес `10.0.2.15/24` по протоколу DHCP (время аренды `valid_lft` — 86400 сек).

Проверка таблицы маршрутизации:

```bash
ip r
```

**Результат:**
```text
default via 10.0.2.2 dev enp0s3 proto dhcp src 10.0.2.15 metric 100
10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15 metric 100
```
* Весь внешний трафик направляется через шлюз по умолчанию `10.0.2.2` (виртуальный маршрутизатор VirtualBox).
* Логи службы `NetworkManager` (`journalctl -u NetworkManager`) подтвердили успешное прохождение цикла DHCP (DORA) и получение конфигурации.

---

### 2. Диагностика и имитация сбоя DNS
1. Проверена работа штатного и публичного DNS-серверов (`1.1.1.1`) с помощью утилиты `dig`:
   ```bash
   dig @1.1.1.1 +short google.com
   ```
2. **Сценарий траблшутинга:** в `/etc/resolv.conf` временно прописан недоступный DNS-сервер (`192.0.2.1`) для разделения проблем сетевого (L3) и прикладного (L7) уровней:
   * `ping -c 3 8.8.8.8` — **успешно** (IP-связность и маршрутизация исправны).
   * `ping -c 3 google.com` — **ошибка** `Name or service not known` (отказ резолвинга имён).
3. Штатная конфигурация `/etc/resolv.conf` восстановлена из резервной копии.

---

### 3. Перехват трафика в реальном времени (`tcpdump`)
Выполнен захват DNS-запросов (UDP/53) на интерфейсе `enp0s3` при обращении к внешнему веб-ресурсу (`curl -I https://rockylinux.org`):

```bash
sudo tcpdump -i enp0s3 -n port 53
```

**Выводы:** зафиксированы исходящие A-запросы от `10.0.2.15` на порт `53` шлюза и ответные пакеты с IP-адресами целевого домена.

---

### 4. Проверка открытых портов и настройка интерфейса WireGuard (`wg0`)
1. Проверены активные сокеты и слушающие службы с помощью `sudo ss -tulnp` (подтверждена работа демона `sshd` на порту `22`).
2. Создан и активирован виртуальный VPN-интерфейс `wg0` с подсетью `10.200.200.0/24`:

```bash
sudo ip link add dev wg0 type wireguard
sudo ip address add dev wg0 10.200.200.1/24
sudo ip link set up dev wg0
```

**Проверка интерфейса и маршрутов (`ip -c a show wg0` и `ip r`):**
```text
3: wg0: <POINTOPOINT,NOARP,UP,LOWER_UP> mtu 1420 qdisc noqueue state UNKNOWN group default qlen 1000
    link/none
    inet 10.200.200.1/24 scope global wg0

default via 10.0.2.2 dev enp0s3 proto dhcp src 10.0.2.15 metric 100
10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15 metric 100
10.200.200.0/24 dev wg0 proto kernel scope link src 10.200.200.1
```

**Технические выводы:**
* Интерфейс работает в режиме `POINTOPOINT,NOARP` (без MAC-адреса и ARP-запросов).
* Значение `MTU` автоматически установлено на `1420` байт (учёт накладных расходов на инкапсуляцию и шифрование пакетов WireGuard).
* Ядро Linux автоматически добавило маршрут для туннельной подсети `10.200.200.0/24` через `wg0`.
* После завершения проверки тестовый интерфейс удалён (`sudo ip link delete dev wg0`).
